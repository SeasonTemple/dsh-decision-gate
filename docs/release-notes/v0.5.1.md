# v0.5.1 - The parity replay runs again, and the desktop RC compatibility is declared

> 2026-10-19 - `npm run check` is green again (the parity replay had been
> crashing since 1.4.0), and the supported DSH range now lives where the
> harness's own loader reads it.

## 中文

### Highlights

| 维度 | 改动 | 为什么重要 |
|---|---|---|
| **parity 回归脚本修好了** | `src/parity.ts` 的 import 补上了 `isAuthorizedMatch`。自 1.4.0 线引入语句级预授权匹配（`0f8f1eb`）以来，这个脚本一跑到授权段就 `ReferenceError` 崩溃——`npm run test:node` 和 `npm run check` 一直是红的。 | 红着的检查比没有检查更糟：它让"测试全绿才算完成"（AGENT.md 第 20 条）变成空话。现在四个离线段全部跑完：30 例豁免解析 + 3 条降级规则、5 条授权决策规则 + 3 条匹配规则、12 例裁判输出解析、11 种配置形状。 |
| **支持范围声明在 harness 真正读的地方** | `package.json` 新增 `engines.dsh: ">=0.2.0-rc.1 <0.3.0-0"`。桌面 RC 的加载器（dsh-app-boot 的 `evaluatePluginCompatibility`）只读 bundle 的 `package.json`——有 `engines.dsh` 就只认它，否则逐个校验 `@deepseek-ai/dsh*` peer 范围对运行时版本。 | 之前范围只写在 `dsh.plugin.json` 里，而 RC 的代码根本不读这个文件——版本不符时 harness 不会跳过 bundle，而是带病加载。现在不符的 DSH 会被显式跳过并报出名字。`dsh.plugin.json` 保留同范围给仍读它的旧版。 |
| **取消不再等裁判** | 门禁是异步的 `tools/pre-execute` 监听器，RC 契约要求异步门观察 `exec.signal`；此前裁判调用只听自己的 60s 预算，用户取消后要白等整个裁判。现在两个裁判后端都优先响应调用方取消，预算第二。 | 取消一个卡住的门禁调用，以前最多白等 60 秒；现在即时返回。没有 `signal` 的执行（旧 RC、功能测试的假 exec）行为不变。 |
| **README 开头有版本适配说明了** | 双语 README 在开头段落之后新增一段：对桌面 RC `0.2.1-rc.2` 逐项验证过的结论——活门禁挂在 `tools/pre-execute` 接缝、支持范围声明位置、`hooks.json` 形态需要可选的 claude-code 桥接插件。 | 0.2.1-rc.2 桌面包里没有打包 `@deepseek-ai/dsh-hooks-claude-code`（295 个包里零个 hooks 包）。活门禁从来不用 hook 形态，所以没有回归——但 0.2.0-rc.2 的可移植性结论描述的是那个构建，不是这个。 |

### Compatibility

| Surface | Before | After | Action |
|---|---|---|---|
| `package.json` `engines.dsh` | 不存在；RC 加载器不读 `dsh.plugin.json` | `>=0.2.0-rc.1 <0.3.0-0`，加载器亲自执行 | 无需操作 |
| 取消受管调用 | 等裁判落地（最长 60s）后才应用取消 | 调用方取消立即中止裁判调用 | 无需操作 |

## English

### Highlights

| Area | Change | Why it matters |
|---|---|---|
| **The parity replay runs again** | `src/parity.ts` imports `isAuthorizedMatch`. Since the statement-level pre-authorization fix (`0f8f1eb`, in the 1.4.0 line), the script crashed with `ReferenceError` the moment the exemption section handed off to the authorization section — `npm run test:node` and `npm run check` have been red ever since. | A red check is worse than no check: it made "tests green or it is not done" (AGENT.md rule 20) an empty rule. All four offline sections now run: 30 exemption parser cases + 3 downgrade rules, 5 authorization decision rules + 3 match rules, 12 judge-output parses, 11 config shapes. |
| **The supported range is declared where the harness reads it** | `package.json` gains `engines.dsh: ">=0.2.0-rc.1 <0.3.0-0"`. The desktop RC loader (`evaluatePluginCompatibility` in `@deepseek-ai/dsh-app-boot`) reads only the bundle's `package.json` — an own `engines.dsh` decides alone, otherwise every `@deepseek-ai/dsh*` peer range is checked against the runtime. | The range previously lived only in `dsh.plugin.json`, a file no RC code reads — an incompatible DSH loaded the bundle instead of skipping it. Now the loader itself enforces the range and skips loudly. `dsh.plugin.json` keeps the same range for older harnesses. |
| **Cancellation no longer waits out the judge** | The gate is an async `tools/pre-execute` listener and the RC contract asks async gates to observe `exec.signal`; the judge call previously watched only its own 60s budget, so a cancelled call sat out the full judge. Both backends now abort on caller cancellation first, budget second. | Cancelling a stuck gated call used to block for up to 60s; it now returns immediately. Executions without a signal (older RC, the functional tests' fake exec) behave exactly as before. |
| **Both READMEs open with a version-compatibility note** | A new paragraph after the intro records what was verified against desktop RC `0.2.1-rc.2`: the live gate rides the `tools/pre-execute` seam, where the range is declared, and that the `hooks.json` form needs the optional claude-code bridge. | `@deepseek-ai/dsh-hooks-claude-code` is not bundled in the 0.2.1-rc.2 desktop build (zero hooks packages among the shipped 295). The live gate never used the hook form, so nothing regresses — but the 0.2.0-rc.2 portability conclusion describes that build, not this one. |
