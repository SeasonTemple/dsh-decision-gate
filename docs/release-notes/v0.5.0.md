# v0.5.0 - The settings card finally renders

> 2026-10-10 - The card 0.4.0 documented and did not deliver now works, and every
> failure path that used to be silent is now visible.

## 中文

### Highlights

| 维度 | 改动 | 为什么重要 |
|---|---|---|
| **设置卡片可用了** | 插件页 bundle 详情里，描述和组件列表之间，现在会出现配置表单：裁判后端、provider/model、matcher、日志路径、五个阈值、豁免前缀、预授权操作全部可编辑，写入即时生效，不用重启、不用手改 YAML。 | 0.4.0 的文档承诺了这张卡片，但它根本不出现——三条失败路径全是静默的，用户看到的是"什么都没有"。 |
| **`authorizedOperations` 生产验证通过** | 预授权的不可逆操作（如 `git push origin main`）现在真的免询问，日志记 `authorized_external` + `authorized: true`。 | 0.4.0 发布时这个功能是空头承诺：配置读不出来、匹配不上、剥离不开，三处都测试全绿但生产不生效。 |
| **失败不再静默** | `require` 失败会注册一个写着原因的占位卡片；服务未注入会直接报错；`remote.session` 未注入时的属性访问崩溃也有了明确报错。 | 0.4.0 之所以能带着一个不存在的设置页发布，就是因为失败只留一句 `console.error`。 |

### Compatibility

| Surface | Before | After | Action |
|---|---|---|---|
| 插件页 | bundle 详情只有描述和组件列表 | 描述和组件列表之间多出配置表单 | 无需操作 |
| `cordis.patch.yml` | 唯一的配置通道 | 仍然是有效通道，与卡片等价 | 无需操作；两种方式写同一处 |
| 客户端 `inject` | `[]`（却使用三个服务） | `['slots', 'configForms', 'remote', 'remote.session']` | 无需操作 |
| 配置键 | 13 个 | 13 个，无增删 | 无需操作 |

### Verification

- `node tests/functional.mjs` → 0 failures（22 项，含 4 项授权用例）
- `python -m pytest tests/test_decision_gate.py tests/test_exempt.py tests/test_analyze.py -q` → 127 passed
- `npx tsc -p tsconfig.json` → 0 errors
- CI：Node 20/22 × Python 3.9/3.12 四矩阵全绿
- 手动：桌面应用重启后插件页出现配置表单；`git push origin main` 日志为 `allow / authorized_external / authorized=True`

### Notes

- **`hooks/hooks.json` 的可移植性仍未验证**：它现在读作 `python hooks/decision_gate.py`，但还没有第二台机器确认 DSH 的 hook 运行器从项目根目录解析这条路径。
- **版本仍是 0.x**：1.x 曾经冒进发布过一次（2026-09-22 的 1.0.0），在设置卡片不存在、预授权不生效的情况下。0.5.0 的意思是"门禁本身可用、配置界面也可用，但并非全部路径都验证过"。
- **`v1.4.0` 的 tag 和 Release 仍然存在**：删除它需要 `gh`，而那条命令在此环境无法执行；重置的事实记录在 CHANGELOG 的 0.4.0 条目里。

## English

### Highlights

| Area | Change | Why it matters |
|---|---|---|
| **The settings card works** | A configuration form now appears on the Plugins page's bundle detail, between the description and the component list: judge backend, provider/model, matcher, log path, all five thresholds, exempt prefixes, and the pre-authorized operations are editable, and a write applies without a restart or a YAML edit. | 0.4.0 documented this card and shipped without it. All three failure paths were silent, so what a user saw was nothing at all. |
| **`authorizedOperations` verified in production** | A pre-authorized irreversible step such as `git push origin main` genuinely stops asking; the log records `authorized_external` with `authorized: true`. | At 0.4.0 this was a promise with nothing behind it: the config read as empty, the match never fired, and the stripping was wrong — three bugs every test passed. |
| **Failure is no longer silent** | A failed `require` registers a placeholder card naming the reason; a missing service errors loudly; the `remote.session` crash has an explicit message. | 0.4.0 could ship a settings page that did not exist precisely because failure left one `console.error`. |

### Compatibility

| Surface | Before | After | Action |
|---|---|---|---|
| Plugins page | bundle detail showed only a description and a component list | a configuration form appears between them | none |
| `cordis.patch.yml` | the only configuration channel | still a valid channel, equivalent to the card | none; both write the same place |
| client `inject` | `[]` while using three services | `['slots', 'configForms', 'remote', 'remote.session']` | none |
| Config keys | 13 | 13, none added or removed | none |

### Verification

- `node tests/functional.mjs` → 0 failures (22 cases, 4 of them authorization)
- `python -m pytest tests/test_decision_gate.py tests/test_exempt.py tests/test_analyze.py -q` → 127 passed
- `npx tsc -p tsconfig.json` → 0 errors
- CI: Node 20/22 × Python 3.9/3.12, all four matrix legs green
- By hand: after a desktop restart the Plugins page shows the form; `git push origin main` logs `allow / authorized_external / authorized=True`

### Notes

- **`hooks/hooks.json` portability is still unverified.** It now reads `python hooks/decision_gate.py`, but no second machine has confirmed that DSH's hook runner resolves that from the project root.
- **The version is still 0.x.** 1.x was claimed once before (1.0.0 on 2026-09-22) while the settings card did not exist and pre-authorization did not work. 0.5.0 means "the gate works and the configuration surface works, but not every path is verified".
- **The `v1.4.0` tag and Release still exist.** Removing them needs `gh`, which this environment cannot reach for that command; the reset is recorded in the 0.4.0 changelog entry instead.
